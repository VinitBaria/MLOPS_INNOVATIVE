# Design decisions, trade-offs, and gaps

The repository has no architecture decision records and only one Git commit. “Why” below is labeled **confirmed from repo (README/comments/commits)** when directly stated or reflected by a code comment/docstring; otherwise it is **my inference** from the implementation. A mere presence of a tool/config is not proof of the author's original motivation.

| Decision | Where | Why (confirmed / inferred) | Alternatives | Trade-offs | What breaks or strains at scale |
|---|---|---|---|---|---|
| Use MovieLens 100K as source | `src/data/download.py::download_movielens` | **confirmed from repo (code):** hard-coded GroupLens dataset URL; no explanation of dataset selection. | Larger MovieLens, licensed or proprietary interactions. **my inference.** | Reproducible public sample vs narrow/old catalog and non-production user behavior. | Sample coverage, changing external download availability, no checksum/version pin. |
| Use three recommendation strategies | `src/models/collaborative.py`, `content_based.py`, `hybrid.py` | **confirmed from repo (comments/code):** SVD, genre cosine, adaptive hybrid; no ADR. | Single model, ALS, nearest-neighbor, learning-to-rank, deep retrieval. **my inference.** | More fallback signals, but higher complexity and uncalibrated score combination. | Model fit and inference memory/latency, especially dense CF matrix and full item similarity matrix. |
| Mean-center and reconstruct rating matrix with truncated SVD | `CollaborativeFilteringModel.fit` | **confirmed from repo (comments/code):** docstring describes latent factors and reconstruction. | Explicit-feedback factorization with bias/regularization, implicit ALS. **my inference.** | Simple decomposition, but no explicit optimization loss or observed/missing confidence model. | Dense conversion grows as O(users × movies); full predicted matrix is also retained. |
| Genre-only content profile with cosine similarity | `ContentBasedModel.fit`, `predict` | **confirmed from repo (comments/code):** genre feature vectors and cosine are explicit. | Plot/text metadata, item embeddings, metadata-based rules. **my inference.** | Explainable/simple features vs coarse similarity and weak cold-start personalization. | Similarity matrix is O(items²) memory; profiles ignore richer context. |
| Adaptive CF/content weighting and threshold 5 | `HybridRecommender._get_weights` | **confirmed from repo (comments/code):** comments say cold-start users get more CB weight. | Fixed blend, learned blend, popularity fallback. **my inference.** | Addresses sparse histories; weights/score scales are not learned or normalized. | Candidate generation/merge work grows with requested K and catalog; behavior can be poorly calibrated. |
| Chronological global 80/20 split | `DataPreprocessor._temporal_split` | **confirmed from repo (comments/code):** function says temporal split prevents leakage. | Per-user temporal split, random split, rolling-origin evaluation. **my inference.** | Mimics future prediction, but all users share one boundary and some may have no train examples. | Evaluation may become unrepresentative under new-user/time patterns. |
| Encode IDs with `LabelEncoder` and persist preprocessor | `DataPreprocessor.fit_transform`, `save` | **confirmed from repo (code):** contiguous encoded indices and preprocessor artifact used by API. | Stable DB ID maps, feature store, online lookup. **my inference.** | Efficient matrix indexing; requires encoder and model artifacts to match exactly. | New IDs are dropped or fallback; full retrains rebuild indices and complicate artifact swaps. |
| Clean duplicate pairs by retaining latest timestamp | `DataPreprocessor._clean_ratings` | **confirmed from repo (code):** sort timestamp then keep last duplicate. | Aggregate ratings, retain event history. **my inference.** | One current rating per user/movie; loses rating-change history. | Must preserve event time and policies for late/out-of-order feedback. |
| Use SQLAlchemy with PostgreSQL attempt and SQLite fallback | `src/database/db.py` | **confirmed from repo (README/code):** README advertises standalone local run; code falls back to SQLite. | One database engine, managed DB. **my inference.** | Convenient local startup but different DB behavior can mask production-only issues. | Silent failover can hide DB outages; no migrations or DB readiness policy. |
| Store new-feedback flag as integer `is_new` | `src/database/models.py::Rating` | **confirmed from repo (code):** pending ratings are counted and reset by retraining. | Event queue, timestamp watermark, append-only event stream. **my inference.** | Simple count trigger; concurrent task races and feedback is not actually used for training. | Duplicate retrains, lost pending-state semantics, ever-growing rating table. |
| Save model and preprocessing artifacts locally with joblib | `src/models/*.py::save`, `DataPreprocessor.save`, `train_pipeline` | **confirmed from repo (code):** explicit local file save/load; no recorded motivation. | MLflow model URI, object storage, ONNX. **my inference.** | Fast Python-native restore; artifact trust, version coupling, and shared-storage problems. | Multi-replica consistency and atomic promotion need a shared immutable artifact store. |
| MLflow is optional | `train_pipeline`, `src/training/mlflow_utils.py` | **confirmed from repo (code):** optional `use_mlflow`, fallback tracking URI, exceptions caught. | Always-on registry or another experiment tool. **my inference.** | Local training can proceed without tracking; experiments may be incomplete and registry path isn't serving path. | Hard to audit many runs or reproduce deployment lineage. |

| Instrument API with Prometheus and Grafana | `src/monitoring/metrics.py`, `docker/*` | **confirmed from repo (README/config):** README describes monitoring; configs wire scrape and dashboard. | OpenTelemetry/hosted monitoring. **my inference.** | Self-hostable metrics; no alert rules, logs, traces, or access controls here. | Cardinality/retention and cross-replica model gauge consistency require operations design. |
| Use Docker Compose for local multi-service stack | `docker-compose.yml` | **confirmed from repo (README/config):** six services composed for local stack. | Single process local run or cloud services. **my inference.** | Convenient integration topology; hard-coded credentials and local artifacts are not production secrets/storage. | Single-host capacity and service lifecycle constraints. |
| Add Kubernetes Deployment, HPA, probes, ingress | `k8s/*.yaml` | **confirmed from repo (config):** config explicitly describes deployment/scaling and health checks. | Compose, managed container app, Helm. **my inference.** | Standard K8s control surface; missing model/artifact/secret/monitoring deployment pieces. | Replicas may not share compatible artifacts; current deployment is incomplete. |

## Weaknesses, tech debt, and unfinished behavior

- **Training input mismatch:** new DB ratings trigger retraining, but `train_pipeline` only reloads MovieLens files. Candidate training ignores submitted feedback (`src/api/main.py::submit_rating`, `src/training/train.py::train_pipeline`).
- **Unsafe promotion sequence:** training overwrites `models/artifacts/production` before quality checks. Rejection doesn't restore previous files (`src/training/retrain.py::run_automated_retraining`).
- **Serving assumes hybrid artifact:** selected production artifact may be CF/content, but startup unconditionally calls `HybridRecommender.load` (`src/api/main.py::load_model_and_preprocessor`).
- **No registry promotion/rollback wiring:** MLflow helper exists but no caller uses `promote_model`; no rollback procedure exists.
- **Drift code is standalone:** no caller, data query, scheduler, persistence, or retrain trigger invokes the detector (`src/monitoring/drift.py`).
- **Metric relevance bug:** evaluator's relevance threshold is unused; all test interactions count relevant (`src/models/evaluate.py`).
- **Rating validation warnings become hard failure:** `validate_ratings` passes only if every check is exactly `PASS`, including checks that emit `WARN` (`src/data/validate.py::DataValidator.validate_ratings`).
- **SQLite/Postgres mode differences:** broad DB connection fallback can conceal Postgres problems; rating user foreign key can reject new users in PostgreSQL, while SQLite may not enforce FK by default (`src/database/db.py`, `src/database/models.py`).
- **Potentially incomplete boot/deploy artifacts:** no `frontend/`, no model volume in K8s, no K8s DB seeding, no MLflow/Prometheus/Grafana K8s manifests (`Dockerfile`, `k8s/*`).
- **Hard-coded operational config:** example passwords, wildcard CORS, no API auth, manually hard-coded model metric thresholds and redundant `.env.example` values.
- **No migrations or pinned dependency lock:** schema uses `create_all`; requirements are only lower bounds.
- **Swallowed failures:** broad catches in evaluation and similarity endpoint can hide errors; retraining catches metadata/MLflow errors and prints notices rather than surfacing structured operational state.
- **No scale validation:** no load tests, ranking quality benchmark, online experiment, retrain concurrency control, or SLO.
